接口与页面实施细则
本文件补足 01 的接口响应与交互约定。软件架构是一个仓库、前后端通过 HTTP 连接、后台 worker 独立执行；不要求部署为多个业务微服务。
1. 通用 HTTP 约定
所有普通 JSON 成功响应为 {data: ..., request_id: "..."}。错误沿用 {error:{code,message,details},request_id}。媒体流、下载文件、204 响应不使用 JSON envelope。服务端随机生成 request_id 并记录日志。
列表为 {items:[],next_cursor:null}；limit 默认 20，最大 100。稳定排序用 created_at+id，行为片段用 start_s+segment_id；cursor 包含查询条件指纹，改变筛选后不能复用旧 cursor。时间参数必须同时提供或同时省略。
主要 HTTP 状态：上传 201，创建后台分析/导入/索引任务 202，普通查询 200，删除登记 202，参数错误 422，不存在 404，状态冲突/重复参数键冲突 409，体积超限 413，上游超时 504。上游不可用 502，缺配置 503 CONFIG_REQUIRED。LLM 失败保留对应 message_id，响应错误 details 可包含该 ID，刷新可查询持久化失败记录。
成功 JSON 的精确数据模型应在 M1/M2 创建 Pydantic 类型并生成 OpenAPI，随后导出前端类型；下表给出必填字段，不能省略为自由 dict。扩展字段必须在类型和测试中同时登记。

4. 关键请求与响应示例
请求：POST /api/videos/video_001/analyses，Idempotency-Key: demo-request-001。
{"provider":"mock","scenario":"normal"}
202 响应示意：
{"data":{"id":"analysis_001","video_id":"video_001","provider":"mock","status":"queued","source_kind":"mock","model_version":null,"progress":null,"warnings":[],"error":null,"created_at":"2026-10-28T00:00:00Z","started_at":null,"finished_at":null},"request_id":"request_001"}
提问请求：
{"client_message_id":"client_001","text":"这头牛采食了多久？","selected_track_id":"track_001","range":{"start_s":0,"end_s":120}}
后台从 session 解析 analysis_id；不允许客户端在同一会话偷偷切换分析。
失败示意：
{"error":{"code":"ANALYSIS_NOT_READY","message":"视频仍在分析，请稍后查询。","details":{"analysis_id":"analysis_001","status":"running"}},"request_id":"request_002"}
为避免 HTTP 重试产生多轮重复聊天：开始处理前写入 user message 和 turn 占用状态；同 client_message_id 相同输入返回已保存结果/处理中状态，不再调用模型；同 ID 不同输入返回 409。另一个新 client_message_id 遇会话忙返回 SESSION_BUSY。

6. 必须完成的交互细节
API 返回真实状态驱动页面，轮询每 2 秒一次；终态停止，页面卸载取消。错误和网络断开显示重试提示。
发送按钮在当前会话处理中禁用；其他页面可用。服务端也做并发保护，不能仅靠禁用按钮。
时间筛选必须 start<end 且位于视频内；输入错误就近显示。清空表示全视频。
改变目标/范围后统计与时间轴一起更新；聊天下一轮附带新选择，历史消息保留自己的范围，不被重绘成新范围。
点击片段后等待 metadata，设置 currentTime 到 start_s，开始播放；到 end_s 暂停。跨片段切换先卸载旧监听，避免叠加。
原生播放器保持可用；bbox overlay 对齐实际视频显示区域而不是整个容器，考虑黑边和缩放。
文档引用显示来源名、版本、页码/章节和摘录；示例资料显示显眼标记。更新/删除后旧回答保留快照并提示来源状态。
不把系统工具原始 JSON、磁盘路径、密钥和完整内部堆栈放进普通用户页面。
7. 前端开发检查顺序
先以 03/08 对接真实本地 API；完成上传/状态/统计/seek 后再做聊天。写类型正确的 API client，处理非 2xx JSON 错误和媒体下载响应。先完成空、加载、失败、成功四种状态，再做样式。
Playwright 至少断言：mock 标记可见、真实任务状态改变、统计卡数值正确、seek 时间改变、对话中出现事实卡、知识抽屉显示原文、导出文件存在且内容正确。截图只证明展示情况，不能代替上述功能断言。
