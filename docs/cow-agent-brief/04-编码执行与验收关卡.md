编码执行与验收关卡
这是给编码 AI 的执行指令。遵循 01 的业务范围，按以下顺序实现。不得把这份文档当成仅供参考的建议清单。
1. 启动前确认与固定决策
先检查项目目录和环境，记录 Python、Node、包管理器版本与已有代码。开发默认 Python 3.12、Node 22；若本机只有与全部依赖兼容的 Python 3.11，可使用并记录。先验证依赖能安装，再提交锁文件。不要在用户全局环境安装软件包。
固定 React + TypeScript + Vite、FastAPI + Pydantic v2 + SQLAlchemy、SQLite、LangGraph、Chroma。前端使用 React Router；网络请求统一封装 fetch，服务端类型是唯一来源，通过 OpenAPI 生成 TypeScript 类型并纳入检查。页面用普通 CSS 和一个图表库即可，不要求复杂组件平台。
默认本机单 API 进程、单视觉 worker、单 Chroma 本地持久化实例。无需 Redis、Celery、Kubernetes 或额外编排平台。时间统一保存 UTC ISO 8601，视频内偏移统一为浮点秒，两者不能混用。
真实大模型和 embedding 的模型名属于部署配置，不凭空填一个型号作为已验证方案。实现兼容工具调用的 API adapter，并提供独立 check-providers 命令：检查 URL、鉴权、工具调用往返、embedding 返回维度。没有凭证时命令输出 NOT_CONFIGURED，不是假成功。
2. 先写出三个可以独立运行的纯函数
validate_analysis_result(result, video_metadata, analysis_context)：结构验证、ID/指纹绑定、时间区间、类别、坐标、跨字段一致性。
compute_track_stats(result, track_id, start_s, end_s)：只读取确定的区间，返回 01 的完整统计；无数据库和 LLM 依赖。
assemble_answer(draft, evidence_registry, context)：只允许引用当前会话和当前分析的已知证据，把事实/视频/知识的 ID 转成实际卡片。
必须先给这些函数写测试，避免把核心计算藏在页面、路由或模型提示词中。
区间交集的唯一基础公式：max(0, min(end, query_end) - max(start, query_start))。禁止用帧数直接乘猜测的 FPS 推导标准区间时长。
校验区间覆盖时比较“合并后的区间并集”，不要只比较总长度。允许相邻 observed 区间在验证视图中合并；保留原始记录。所有浮点一致性比较采用明确小容差（建议 1e-6 秒），媒体探测容差仅用于源视频 duration 比对，不扩大到任意行为越界。

5. 后台任务必须处理的边界
领取任务使用条件更新 queued→running 并检查受影响行数，防止重复领取。先提交领取事务，再执行分析。每隔约 5 秒更新 heartbeat；超时阈值可配置，默认 60 秒用于失联检测，模型执行总超时单独配置。
command adapter 通过子进程启动外部程序；执行期间 heartbeat 不能停止。采用轮询进程状态或独立心跳逻辑。结果成功发布前验证所有数据，数据库事务必须全有或全无；孤立临时文件可清理，不作为成功证据。
worker 启动和定期维护时把超过阈值的旧 running 任务置 failed。不要立即重置仍有正常 heartbeat 的任务。重试创建新 analysis，保留原错误记录。
进度未知时为 null，界面显示“处理中”；不得用定时器模拟真实百分比。mock 的演示百分比也必须标明模拟。
6. RAG 的最小真实实现
PDF 用一个文本提取库（建议 pypdf），MD/TXT 读取为文本。分块函数输出 text + page/section + ordinal。同一段落超过块长再切分；不要丢掉文字或重复写入相同 chunk_id。
lexical 检索：NFKC 规范化、拉丁字符小写、提取中文 2/3 字符 n-gram 和词项，以真实文本重合度排序；没有公共词项返回空。此模式属于离线工程验收。
vector 检索：通过 embedding adapter 实际请求向量；写入 Chroma 时显式指定 embedding。集合采用 cosine 距离并记录；score 可以定义为 1-distance，不是概率。距离阈值设为配置，并在固定正例/负例上确定。不可直接复用 lexical 的分数阈值。
文档更新：新版本 ready 后原子切换 active_version；新版本失败时保留旧 ready 版本。查询先拿候选，再过滤数据库中的 active_version/deleted_at；需要补取时有界扩充候选，返回数量仍不超过 top_k。删除操作先让数据库查询不可见，再异步清理向量。
引用快照保存当时的标题、片段、页码与版本。删除文档后，历史回答不能悄悄指向新版本；界面显示“来源已删除/已更新”，可以显示该对话保存的引用快照。新检索不返回旧版本。
7. 防止实现成空壳的硬性检查
页面数据必须通过 API 读取；fixture 只由明确的 mock/seed 路径产生，不能写在 React 页面中冒充请求结果。
真实 API provider 必须支持 tools/tool_calls，不能只有普通聊天请求。
graph 的工具节点必须实际调用统计/数据库/检索函数，不能返回预写问答。
示例知识与专业资料用 is_demo 分开；只有示例知识时不输出养殖专业结论。
实际保存后重新启动 API，检查数据是否仍可用。
至少一次 Playwright 操作真实本地服务，不可将所有 API 都 mock 掉后声称端到端成功。
页面所有可见按钮必须有效；未做功能移出第一版界面，不能保留“敬请期待”代替必做项。
禁止以增加大量 UI 动画、模型名或统计大屏替代核心闭环。
8. 编码结束时的固定报告格式
最终报告包含：目标目录、已完成模块、启动命令、测试矩阵、实际截图路径、未验证外部依赖、已知限制、与视觉同学的接入步骤。每个测试标 passed/failed/not_run；软件离线验收和外部 live 验证分成两张表。
