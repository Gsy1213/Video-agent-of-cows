1. 目标、职责与范围
实现一个中文网页系统：用户上传牛舍视频，后台接入视觉分析结果；页面展示行为时间轴、时长统计和视频证据；用户围绕当前视频提问，智能体查询行为数据并按需检索养殖资料，回答时给出证据。
四个角色：视觉系统看画面，程序算数据，RAG 查资料，智能体选择工具并解释。
两人分工：
A：数据、标注、模型训练、真实推理、跟踪、行为片段与有效观察区间的产生。负责模型效果和时序估计方法。
B（本次编码 AI）：完整软件、视觉适配器、结果验证与存储、按约定区间计算统计、RAG、智能体、前端、后台任务、测试和运行说明。
共同：行为名称和定义、结果协议、时长统计口径、真实接入测试。软件中的统计函数成为唯一实现，供 A 对照；若 A 返回 summary，软件重新计算并检查，不直接信任外部总数。
必做：视频上传/播放，异步任务，导入和接入模型结果，行为时间轴，单视频内目标统计，片段定位，对话，知识文档管理与检索，证据引用，Markdown/JSON 报告导出。
第一版边界：固定摄像头、离线短视频、单用户本机/可信开发环境；先实现 2～5 分钟演示，上传时长上限默认 10 分钟、文件上限默认 500 MB，配置可修改。行为类别由分析结果提供，不在前端硬编码。track_id 只表示一次分析中的轨迹，不代表真实耳标身份。
本次不做：模型训练、自动标注、视觉识别或跟踪算法研发、跨摄像头/跨天个体识别、实时摄像头接入、疾病诊断、自动养殖设备控制、多租户权限系统、多智能体协商、复杂知识图谱、支付、生产公网部署。禁止为了显示效果编造模型指标或正常/异常阈值。
2. 技术架构与运行模式
采用一个仓库，模块化代码。应用不需要拆成多个微服务。
前端：React、TypeScript、Vite，简单 CSS 或熟悉的轻量 UI 库；原生 video 元素；图表可使用一个成熟库，避免同时引入多个。
后端：Python 3.11 或 3.12、FastAPI、Pydantic v2、SQLAlchemy、SQLite（WAL 和 busy timeout）。选择一个 Python 版本实际验证并记录。
工作进程：独立 Python worker，从持久化任务表领取任务；开发版单 worker，API 不执行阻塞式视频分析。
智能体：LangGraph 的状态图，单智能体加工具；可配置支持结构化工具调用的聊天模型 API。
RAG：真实向量模式使用 Chroma 持久化服务，由 API 进程统一读写；可配置 embedding provider；离线模式使用本地真实文本的关键词/中文字符 n-gram 检索，并在界面和结果里标明模式。
